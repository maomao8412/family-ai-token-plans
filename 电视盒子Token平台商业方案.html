一、模式转译：不是中国版 OpenRouter，是家庭 AI 的水电煤

OpenRouter 服务开发者；这个产品服务家庭。转译错了，一切白做。

OpenRouter 的本质是模型聚合统一计费一个 Key 调所有模型。直接照搬到家庭会失败，因为家庭用户不开发应用、不关心模型名字、没有 API Key 概念。需要转译的是它的三层结构，而不是它的界面：

层OpenRouter（开发者）本方案（家庭）
聚合层数十家模型 API 接入接入 3–5 家国内已备案大模型（DeepSeek、豆包、GLM、Kimi、通义级）
路由层开发者手动选模型无感路由：按任务类型、成本、延迟自动分配模型，用户永远不选
计费层按 token 充值 Credit，加价 5–20%家庭钱包：包月订阅含基础额度 + 超量按量计费，全家共享一个池子
入口层API Key / 网页盒子+电视（语音与大屏）+ 手机（钱包与管理）
护栏层无内容安全与未成年人模式：家庭公共屏幕的硬约束，也是与 OpenRouter 最本质的差异

一句话定位：家里的 AI 电表。电力公司不生产电器，它计量和输配电；这个平台不生产模型，它把所有合格模型变成家里一块统一计量的"AI 电表"，插上盒子全家通电。

二、为什么是现在：三个窗口同时打开

可行性调研的三个结论，构成这个方案的时间窗

窗口一：屏幕在，付费缺口也在

4.39 亿台智能电视、52% 日均开机率、5.6 小时日均使用，客厅屏幕是真实的家庭高频场景；但海信、TCL 等厂商接入大模型后全部免费附赠——厂商证明了需求，却没人证明收费。免费附赠的是"功能"，没被提供的是"服务"：全家人各自被记住的、可管理的、按需扩展的 AI 服务。

窗口二：模型价格战把成本压到可包月

国产主力模型每百万 token 输入价格已进入个位数区间，价格战仍在继续。对开发者是坏消息，对家庭包月是好消息：一个重度家庭的月成本可以压到两位数人民币，这让"29 元包月随便问"在成本端成立。纯转售会随着价格战继续变薄——所以商业模式重心必须放在场景包（第五节），token 差价只做底仓。

窗口三：中立平台的位置还空着

小米（电视份额第一+自研小爱）、华为（智慧屏+盘古）、海信/TCL（聚好看+接入 DeepSeek）都做过"电视+AI"，但它们都是利益冲突方：要么推自家模型，要么绑定自家生态。家庭市场的"中立聚合层"——不偏袒任何模型、按效果与成本路由——这个位置目前没有人占。OpenRouter 之所以存在，正是因为模型厂商互相竞争、需要一个中立方；同样的结构条件在中国家庭市场刚刚成熟。

三、产品架构：一台盒子，三个终端，一层平台

电视是脸，盒子是心脏，手机是钱包——token 调用与电视解耦

盒子的职责边界（决定成本与体验）

盒子做三件事：远场语音采集（4 麦阵列+回声消除，对着电视 3 米说话可用）、会话管理（家庭成员声纹识别——爸爸问的话和女儿的作业问题路由策略不同）、大屏渲染。不做本地大模型推理：2026 年的百元级 ARM 盒子跑不动合格的多模态模型，强行本地化只会拖垮体验；推理全部上云，走平台路由。这个取舍让 BOM 控制在约 280 元（RK3566 级 + 2G + 32G + 麦克风阵列），整机成本约 340 元，定价 499–599 元仍有健康毛利。

手机端为什么必须先行

可行性调研的结论之一：token 商业化闭环应在手机端完成——支付、账单、家长控制都发生在手机上，电视保持"零支付界面"。这同时解决两个问题：付费主体清晰（家长手机充值、全家消费），以及电视端合规风险最小化（公共屏幕不放任何交易入口）。

四、路由引擎与家庭钱包：平台的两个核心资产

用户永远不选模型——路由引擎替家庭管效果和成本，钱包替家庭管预算

无感路由的三层规则

规则逻辑示例
任务分类意图识别后映射任务类型：速答/长文/数学推理/图像理解/口语陪练"明天穿什么"→轻量快模型；"讲这道奥数题"→推理模型
成员画像声纹/账号绑定成员档案：儿童账号强制走安全模型+教育路由，老人账号偏好慢速大音量+方言识别女儿问作业→教育包模型+家长周报；爷爷问天气→默认模型+放大字幕

家庭钱包的四个设计点

① 成员子额度：家长给每个成员设月度 token 额度，孩子超额度即停，防失控；② 用量可视化：电视端屏保显示"本月全家 AI 用量"进度条，把消耗变成家庭话题；③ 场景包隔离计费：教育包等专项额度单独计量，家长买得明白；④ 闲时转赠：月底未用完额度可转下月或转赠亲友（获客机制）。

六、合规与安全：这个生意的入场券，不是成本项

面向家庭公共屏幕的 AI 服务，护栏本身就是产品力

三条合规主线：① 模型侧——只接入已通过生成式 AI 服务备案的模型，自身按"调用已备案模型的应用"路径完成登记，不自研模型就不踩备案深水区；② 内容侧——平台层内置审核管道（涉政涉黄涉暴拦截+未成年人模式强过滤），电视端默认开启青少年安全档；③ 数据侧——家庭语音数据本地唤醒、云端脱敏，隐私政策明确"声纹不上传原始音频"，这是家庭产品的信任底线。

护栏反过来是卖点：家长愿意为"孩子安全使用 AI"付费，这恰恰是模型厂商直连 API 给不了的东西——安全不是这个方案的成本，是第一个场景包。

七、竞争博弈：中立性的价值与大厂的三种反应

大厂做不了这件事的原因，就是这个方案存在的理由

预判三种反应：模仿——某厂商推自家"AI 盒子"，但单一生态无法提供多模型路由，先天残缺；收编——大厂补贴硬件打价格战，对策是避开硬件规模战，靠 B 端授权与运营商渠道走量，硬件只承担筛选用户职能；采购——最好的结局：某 TV 厂商或 IPTV 运营商直接把平台层买进去预装，本方案从零售转型为能力输出。运营商是天然的盟友：IPTV 有存量盒子、有家庭缴费通道、有"增值业务"运营经验，唯独没有 AI 能力——这是一条比电商卖盒子更宽的渠道。

九、风险清单与对冲

按杀伤力排序

风险杀伤力对冲
客厅 AI 需求伪命题：电视语音交互频率远低于预期高Phase 1 前置验证 Go/No-Go 门；软件先行，硬件可推迟；手机端兜底承接账户体系

模型厂商绕过平台直连家庭中价值重心放在路由/护栏/场景/家庭多成员体系——这些是模型厂商不会做的"最后一公里"
token 差价被价格战清零中定价结构中差价占比≤30%，利润重心在场景包（第五节）
语音数据隐私事件高（一次性致命）本地唤醒、原始音频不出盒、声纹本地化；把隐私承诺写进硬件规格而非只是隐私政策

这个方案成立与否，最终不取决于技术——路由、钱包、护栏都是确定性工程——而取决于一个待验证的家庭行为假设：一家人是否真的会在客厅里，共同使用同一个 AI。12 个月路线图里所有的闸门，都是为了尽早知道这个假设的真伪。
